# 먹이사슬 술래잡기 3.2.1 — 2D 숲속 RPG

4학년 「생물과 환경」의 먹이관계를 배우는 실시간 학급 웹게임입니다.

## 3.2.1 메뚜기 장애물 뛰어넘기

- 메뚜기의 ‘멀리 뛰기’가 바라보는 방향으로 0.75초 동안 약 330만큼 도약합니다. 방향키를 놓은 상태에서도 뛰며, 공중에서 반대 방향을 눌러도 도약을 끝까지 마칩니다.
- 점프 중에는 나무와 바위를 통과하고 개구리에게 잡히지 않습니다. 착지할 곳이 장애물 안이면 가장자리의 안전한 위치로 옮깁니다. 맵 경계 밖으로 나가지 않습니다.
- 높이 뛰어오르는 움직임과 작아지는 그림자를 표시합니다. 벼는 착지한 뒤 먹으며, 재사용 대기시간은 4초입니다.
- 기존 초당 최대 4회 동기화와 전송 형식을 그대로 사용합니다. 점프를 위한 추가 접속이나 전송 항목은 없습니다.

**3.2에서 업데이트:** `engine.js`, `render.js`, `index.html`, `demo.html`을 교체하세요. 압축 안 파일 전체를 올려도 됩니다. 배포가 끝나면 교사·학생 창을 모두 새로고침합니다. Firebase 설정이나 규칙을 다시 바꿀 필요는 없습니다.

## 3.2 Firebase 무료 사용량 절약

- 게임 상태는 초당 최대 4회 동기화하며, 바뀐 부분만 보냅니다. 이름·생물 외형·배경 배치는 움직임과 분리했습니다.
- 멈춰 있는 학생의 같은 조작값은 한 번만 보냅니다. 이동 중에는 방향 변경·특수 행동을 즉시 반영하고, 같은 방향으로 이동할 때만 0.4초 간격으로 유지 신호를 보냅니다.
- 대기·일시정지·모둠 토의 중에는 달라지지 않은 게임 상태를 다시 쓰지 않습니다. 교사 연결 확인은 4초 간격이며, 학생은 자기 모둠의 토의 결과만 구독합니다.
- 기존 이동 애니메이션과 화면 보간, 잡힘 판정, 역할 교대, 모둠 보드 기능을 유지합니다.

**3.1.1에서 업데이트:** `app.js`, `network.js`를 교체하고 **`sync.js`를 새로 추가**하세요. 압축 안 파일 전체를 올려도 됩니다. 교사·학생 창을 모두 새로고침한 뒤 입장합니다. `database.rules.json`은 3.1.1과 같은 규칙입니다. 이전 수정 전 버전을 쓰고 있다면 아래 3.1.1 규칙 적용 안내도 확인하세요.

무료 사용량의 기준·실측 조건·예상 전송량은 **`FREE_TIER_CHECK.md`**에, 원시 측정값은 **`USAGE_CHECK.json`**에 있습니다. 현재 계정의 월 누적 사용량은 이 파일로 조회할 수 없으므로 수업 전 **Firebase → Realtime Database → Usage**에서 Downloads와 Connections를 확인하세요.

개발 검증: `npm test`로 게임·전송 검사를 실행합니다. 로컬 Firebase 연결 검사는 `npm install --prefix tests` 후 `npm run test:firebase`, 동시접속·전송량 검사는 `npm run test:load`로 실행합니다. Node와 Java 21 이상이 필요하며 `demo-foodtag` 에뮬레이터만 사용합니다. 실제 Firebase 사용량은 발생하지 않습니다.

## 3.1.1 학생 입장 권한 오류 수정

학생 참여 정보를 완성하기 전에 퇴장 정리 작업을 예약하던 순서를 수정했습니다. 학생은 완전한 참여 정보를 먼저 오프라인 상태로 저장하고, 퇴장 정리 예약을 마친 뒤 온라인으로 표시됩니다. 입장 정보 저장이 실패하면 빈 게임 화면으로 넘어가지 않습니다.

기존 배포를 고칠 때는 **`network.js`, `app.js`, `database.rules.json`**을 GitHub에서 교체하세요. 이어서 **Firebase → food-chain-tag → Realtime Database → Rules**에도 새 `database.rules.json` 전체를 붙여 넣고 게시해야 합니다. GitHub 파일 교체만으로 Firebase 규칙이 갱신되지는 않습니다. Vercel의 Firebase 설정값은 앞서 저장한 값을 사용합니다. 교사와 학생 창을 모두 새로고침한 뒤 다시 입장하세요.

개발 검증: `npm test`는 게임 로직을 검사합니다. Firebase 규칙과 입장·퇴장·재접속 검증은 Node와 Java 21 이상이 있는 환경에서 `npm install --prefix tests` 후 `npm run test:firebase`로 실행합니다. 이 검사는 `demo-foodtag` 로컬 에뮬레이터만 사용합니다.

## 3.1 도트 게임 그림체

생물 16개 방향 그림과 나무·바위·풀숲·벼를 같은 도트 RPG 스타일로 교체했습니다. 입장 화면·게임·먹이사슬 보드·인쇄 카드에 모두 적용했습니다. 땅·흙길·물가도 작은 격자로 그리며, 확대/축소할 때 이미지를 부드럽게 보간하지 않아 도트 윤곽이 선명하게 표시됩니다.

업데이트할 때 소스 전체를 교체하세요. Firebase 설정과 규칙, 학생 공통 링크는 그대로 사용합니다.

## 3.0 변경 사항

- 넓은 사각형 2D 숲 맵과 작은 동글동글한 생물 아바타. 특정 서비스의 이미지나 코드를 복제하지 않은 자체 제작 그림입니다.
- 정면·왼쪽·오른쪽·뒷모습이 실제 이동 방향에 따라 바뀝니다. 걷기·뛰기와 매의 떠 있기 연출을 더했습니다.
- 여러 갈래 흙길, 숨는 풀숲, 나무, 바위, 얕은 연못과 다리를 배치했습니다. 연못은 이동할 수 있는 얕은 습지입니다.
- 라운드가 끝나면 방금 맡은 역할의 먹이관계 한 문제를 풉니다. 다시 생각하기와 정답 해설을 제공하며, 교사가 다음 라운드를 시작할 때까지 기다립니다. 퀴즈 응답은 각 기기에서만 확인하며 교사에게 전송·집계하지 않습니다.
- 역할 교대는 생물이 다른 종류로 변하는 과정이 아니라, 학생이 다른 생물 역할을 맡는 놀이임을 안내합니다.
- 나무·바위 충돌과 시야 차단, 풀숲 숨기, 장애물을 돌아가는 탭 이동, 미니맵, 외형 세 가지 선택을 유지했습니다.

기존 버전에서 업데이트할 때는 소스 전체를 교체하고 새 수업을 여세요. 2.0/2.1의 Firebase 설정·규칙·학생 링크를 그대로 사용할 수 있습니다. 1.0에서 바꾸는 경우에는 `database.rules.json`도 갱신하세요.

## 들어 있는 기능

- 학생 공통 링크에서 모둠(1~6)과 모둠 안 번호(1~6) 선택, 학생 로그인 입력 없음.
- 같은 숲에서 최대 36명 참여. 메뚜기·개구리·뱀·매를 골고루 배정하고 네 라운드에서 역할 교대.
- 조작판, 화면 눌러 이동, 방향키/WASD. 스페이스/행동 버튼으로 점프·혀·숨기·내려오기.
- 먹이관계는 벼 → 메뚜기 → 개구리 → 뱀 → 매. 잡히면 2.5초 뒤 재출발, 출발 후 3초 보호.
- 컴퓨터 생물 보충, 풀숲 숨기, 탐험 기록, 모둠 공동 먹이사슬 보드와 제출.
- 교사 시작/멈춤/역할 교대/새 수업/모둠 결과/JSON 내려받기.
- `cards.html`: 실제 카드 놀이 안내 1쪽 + 역할 카드 각 8장과 벼 카드 8장(5쪽), A4 인쇄.
- Firebase 설정이 없어도 ‘혼자 먼저 연습하기’와 ‘교사 화면 미리 체험’ 사용 가능. 이 모드는 다른 기기와 연결되지 않습니다.

## 바로 체험하기

`demo.html`을 더블클릭하면 컴퓨터 생물과 혼자 놀 수 있습니다. 이 파일은 그림과 게임 코드를 포함하며 별도 설치·Firebase 설정 없이 실행됩니다. 학급 동시 접속은 아래 설정 뒤 `index.html`에서 사용합니다.

## 1. GitHub에 올리기

압축을 풀고 **이 폴더 안 파일 전체**를 저장소 최상위에 올립니다. 저장소를 열자마자 `index.html`이 보여야 합니다.

별도 설치·빌드가 없는 HTML/JavaScript 프로젝트입니다. `assets/animals-pixel.png`, `assets/forest-props-pixel.png`, `projection.js`, `api/config.js`, `database.rules.json`도 함께 올립니다.

## 2. Firebase 설정

기존 앱과 구분되는 새 Firebase 프로젝트를 사용하는 것이 편합니다. 이 게임은 **Cloud Firestore가 아닌 Realtime Database**를 사용합니다.

1. Firebase 프로젝트 설정에서 웹 앱을 등록하고 `firebaseConfig`를 복사합니다. `databaseURL`을 포함해야 합니다. Realtime Database를 뒤늦게 만들었다면 웹 앱 설정 값을 다시 확인하세요.
2. **Build → Authentication → Sign-in method**에서 **Anonymous(익명)**와 **Email/Password(이메일/비밀번호)**를 사용 설정합니다.
3. **Authentication → Users → Add user**에서 교사 이메일과 비밀번호를 만듭니다. 학생 계정은 만들지 않습니다. 화면에서 학생에게 로그인 정보를 요구하지 않으며, 내부에서 익명 인증을 사용합니다.
4. **Build → Realtime Database**를 만들고 **Rules**에 이 폴더의 `database.rules.json` 전체를 붙여 넣어 게시합니다. 다른 프로젝트와 공유 중인 데이터베이스의 규칙을 덮어쓰면 다른 앱에 영향을 줄 수 있으므로 새 프로젝트를 권장합니다.
5. Authentication 설정의 **Authorized domains**에 실제 Vercel 도메인을 추가합니다.

학생은 자신의 조작만 쓰고, 숲의 위치·잡힘·점수·역할은 교사 계정만 기록하도록 규칙을 구성했습니다. 모둠 보드는 같은 모둠 학생들만 함께 수정합니다.

## 3. Vercel 연결

GitHub 저장소를 Vercel로 가져옵니다.

| 항목 | 값 |
|---|---|
| Framework Preset | Other |
| Build Command | 비워 두기/Override를 켜고 비워 두기 |
| Output Directory | 비워 두기 |
| Install Command | 비워 두기 |

**Settings → Environment Variables**에서 다음 한 항목을 추가하세요.

이름: `FIREBASE_WEB_CONFIG`

값: `firebaseConfig`의 **내용만 JSON으로** 넣습니다. `const firebaseConfig =`나 세미콜론, 코드 블록 표시를 넣지 않습니다. 키와 문자열에 큰따옴표를 씁니다.

```json
{
  "apiKey": "웹앱의 apiKey",
  "authDomain": "프로젝트.firebaseapp.com",
  "databaseURL": "Firebase 콘솔에 표시된 정확한 Realtime Database URL",
  "projectId": "프로젝트 ID",
  "storageBucket": "웹앱 설정의 storageBucket",
  "messagingSenderId": "웹앱 설정의 messagingSenderId",
  "appId": "웹앱 설정의 appId"
}
```

Production과 Preview에 적용하고 **Redeploy**합니다. 웹 앱 설정 값은 브라우저에 전달되는 설정이며, **서비스 계정 JSON·private_key를 넣는 곳이 아닙니다.**

환경 변수 대신 `config.js`의 `{}` 안에 Firebase 웹 앱 설정을 넣는 방법도 있습니다. Vercel 배포에서는 환경 변수 방식을 권장합니다. 별도 Firebase Admin SDK나 유료 서버는 필요하지 않습니다. Firebase 사용량과 요금은 자신의 콘솔에서 확인하세요.

## 4. 수업 열기

- 학생 주소: `https://내주소.vercel.app/?class=class4`
- 교사 주소: `https://내주소.vercel.app/?mode=teacher&class=class4`

1. 교사 주소에서 2단계에서 만든 교사 계정으로 로그인합니다. 최초 로그인 때 교실 소유자가 등록되고 새 수업이 열립니다.
2. 교사 화면의 **학생 공통 링크 복사**로 링크 하나를 공유합니다. 복사 권한이 없으면 직접 복사할 수 있는 창이 열립니다.
3. 학생은 모둠과 번호를 선택합니다. 같은 모둠에서 다른 번호를 고릅니다. 모둠별 별도 링크나 수업 코드 입력은 없습니다.
4. 학생 수를 확인하고 첫 라운드를 시작합니다. 첫 역할은 입장 순서로 골고루 배정됩니다. 라운드가 끝나면 학생들은 한 문제를 풀고, 교사가 답을 함께 확인한 뒤 다음 라운드를 시작합니다.
5. 메뚜기 → 개구리 → 뱀 → 매 → 메뚜기 순서로 **역할을 교대**합니다. 네 라운드에 모두 참여한 학생이 네 역할을 체험합니다. 늦게 입장한 학생은 남은 라운드부터 참여합니다.
6. ‘먹이사슬 정리하기’를 누르면 학생들이 모둠 공동 보드로 이동합니다. 모둠원이 함께 연결하고 설명을 쓴 뒤 대표 한 명이 제출합니다. 교사 화면에서 모둠 버튼으로 결과를 봅니다.
7. 남는 시간에 ‘실제 카드 놀이로 이어가기’를 열어 같은 관계를 몸으로 표현합니다.

**교사 창을 켜 두세요.** 교사 브라우저가 게임 판정을 담당합니다. 다른 탭/앱으로 이동하면 자동으로 일시 정지합니다. 수업 중에는 교사 PC 화면을 계속 켜 두고, 교사 조작 창 하나만 사용하세요. 교사 창을 새로 열면 연결된 기존 창이 닫힌 뒤 약 10초 후 같은 계정으로 재연결할 수 있습니다. 새로고침 후에는 일시 정지 상태로 복구됩니다. 갑작스런 종료에서는 마지막으로 저장된 상태가 복구됩니다.

다른 반을 운영하려면 주소의 `class=class4`를 `class=class5`처럼 바꾸고 학생·교사 주소에 같은 값을 사용합니다. 이미 소유자가 등록된 교실은 그 교사 계정으로 관리합니다. 학생 링크를 새로 열려면 로그아웃 없이 학생 화면 주소로 돌아가면 됩니다. 학생 입장을 시험할 때는 교사와 별도 브라우저/시크릿 창을 사용하세요.

## 수업 전 점검과 실행

```sh
npm test
python3 -m http.server 8000
```

로컬 주소는 `http://localhost:8000`입니다. 로컬에서는 `api/config`가 실행되지 않으므로 연결 시험에는 `config.js`를 사용합니다. 파일을 더블클릭한 `file://` 주소에서는 모듈이 실행되지 않습니다.

수업 전에는 실제 Vercel 배포 후 교사 PC와 학생 기기 2대로 입장·이동·잡힘·역할 교대·모둠 보드 공유를 확인하고, 가능하면 학급 기기로 리허설하세요. 이 소스는 게임·전송 검사와 Firebase 에뮬레이터의 규칙·동시접속 검증을 수행했습니다. 결과와 범위는 `CHECKS.txt`, `FREE_TIER_CHECK.md`에 있습니다. 실제 학교의 태블릿과 무선망에 따른 전송 지연은 현장에서 확인해야 합니다.

접속 실패: 익명 인증 사용 설정, Realtime Database URL, 규칙 게시, Vercel 재배포를 확인하세요. 교사 로그인 실패: 이메일/비밀번호 방식 사용 설정과 Users에 만든 계정을 확인하세요. 다른 앱의 서비스 계정 키는 필요하지 않습니다.

## 구현과 출처

- 교사 브라우저가 20Hz로 판정하고 약 7Hz로 압축된 상태를 공유합니다. 학생 조작은 최대 8Hz로 전송하고 화면은 보간해 표시합니다. 오래된 조작은 버리고, 재접속 때 다시 참여 상태를 등록합니다.

- Firebase 공식 문서: [웹 SDK CDN](https://firebase.google.com/docs/web/alt-setup), [Realtime Database 읽기/쓰기](https://firebase.google.com/docs/database/web/read-and-write), [오프라인·연결 상태](https://firebase.google.com/docs/database/web/offline-capabilities), [익명 인증](https://firebase.google.com/docs/auth/web/anonymous-auth), [이메일 인증](https://firebase.google.com/docs/auth/web/password-auth).
- 생물·숲 소품 이미지: 내장 ImageGen으로 기존 시트를 도트 그림체로 편집한 투명 4×4 생물 방향 시트와 2×2 소품 시트. 최종 프롬프트는 `ASSET_PROMPT.txt`에 있습니다.
